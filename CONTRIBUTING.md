# Contributing to Cambra

Cambra is a young, fast-moving language substrate built by a small team. Right now, we're not accepting external pull requests. That's not a statement about the quality of contributions we'd get — it's that the type system, dataflow semantics, and core abstractions are still settling, and reviewing and integrating outside code costs time we don't have while things are moving this fast. Keeping full control over the codebase during this phase matters more than opening the gates early.

This will probably change. See the last section.

## What's welcome

- **Bug reports.** If something's broken or behaves unexpectedly, file an issue. See the bug report template for what's useful to include.
- **Language and design discussion.** Disagreement with a design choice, "have you considered X," questions about why something works the way it does — all of this is welcome as issues or discussion threads.
- **Questions.** If you're working through Cambra and get stuck, ask.
- **Writing about Cambra.** Blog posts, notes, threads working through the type system or the dataflow model — we're glad to see it, and we'll often read and link to it.

## What's not accepted right now

External pull requests. If you open one, we'll likely close it and point here — that's about where the project is, not a judgment on the patch.

## Small patches

If you've got a small, clearly-correct fix — a typo, an off-by-one, a bad error message — don't let the no-PRs rule stop you from telling us. Attach a patch, or just describe the fix, on an issue. If it's right, we'll apply it ourselves as a commit from the team, with credit to you in the commit message. There's no formal process for this — just open the issue.

## What to expect

- Issues are read. All of them. Responses aren't guaranteed, and we won't always have the bandwidth to engage deeply.
- "Won't fix" is a valid resolution. We're not obligated to act on every request, and we won't be held hostage by issue volume.
- The roadmap is set by the team, not by vote. Feature requests are welcome, but we decide what gets built and when.

Everyone participating in issues and discussion is expected to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## This will probably change

Closed contribution is where we're starting, not where we intend to stay. As Cambra and the team around it grow, we expect to open up contribution — likely gated by a CLA to keep IP clean. Until then: if you want to build on Cambra, fork it and see what happens; if you want to help shape where it goes, file issues and take part in the discussion.
